# SR-263: Reopen a resolved request with a reason

As a reporter or an assignee, I want to reopen a resolved request with a reason so that unfinished work can return to the queue without losing its history.

## Acceptance criteria

- Only a Resolved request can be reopened. An Open request is rejected. A request that is Pending approval is rejected, because it was never resolved.
- The reporter or the assignee may reopen it. Anyone else is rejected.
- A reason is required and must be at least 15 characters.
- The reason is stored through the existing comment API. Do not add a comments table or a new visibility system.
- Status becomes Open. Priority is unchanged.
- An audit row records who reopened the request, when, and the comment id. Use the existing audit table.
- Existing resolve tests and existing comment tests stay in the run. Add tests for a legal reopen, a too-short reason, the Pending approval rejection, and the unchanged priority.
- The feature passes CI and is ready for release. Nothing is deployed.

## Complication introduced during implementation

The requester must be able to read the reason. The comment skill defaults audience to staff. Do not invent a second visibility model. On this comment only, set audience to requester. Put that field in the path-scoped reopen instructions, and leave the comment skill's default as it stands.
